# Photo Analysis Engine

## 1. 目标

将输入照片转换为标准化的 Photo Analysis Profile，作为后续风格匹配与技术选择的事实基础。

- 本引擎只负责描述照片的客观事实，**不决定最终风格**，也不输出风格评分。
- 风格匹配、六维评分、总分带判定和自然原生兜底（natural_native_professional）按 SKILL.md 与 `engine/` 各引擎文件的口径执行；规则红线以 `rules/photography-rules.md` 为准，该文件是唯一总规则源。
- 本文件与总规则源冲突时，以总规则源为准。

## 2. 在决策流程中的位置

1. **Photo Analysis**（本引擎）：输出 Photo Analysis Profile。
2. **风格匹配**：基于 Profile 做六维评分。
3. **技术选择**：基于 Profile 与选定风格，选择 techniques，如 Dodge & Burn。techniques 不是 styles。

Profile 中的分析维度为六维评分提供输入，对应关系如下：

| 六维评分维度 | 主要输入的分析维度 |
|---|---|
| Subject | Subject、Composition |
| Light | Light |
| Color | Color |
| Narrative | Narrative、Scene |
| Texture | Quality（噪声、清晰度、纹理、压缩） |
| Preservation | Risk、Quality |

Depth 作为空间信息辅助各维度判断，不单独对应某一评分维度。

## 3. 分析维度

每个维度都必须输出。某项内容无法确认时，按第 4 节原则 4 处理。

1. **Subject（主体）**
   - 主体类别
   - 主体数量
   - 主体权重
   - 主体与环境的关系
2. **Scene（场景）**
   - 场景类别：自然、城市、建筑、室内、人文、旅行、动物、美食等
3. **Light（光线）**
   - 主光方向：逆光、侧光、顶光、平光
   - 光质与硬度
   - 反差
   - 阴影结构
   - 环境亮度
4. **Color（色彩）**
   - 色温
   - 综合色相
   - 饱和度
   - 主色与互补色
   - 局部色彩异常
5. **Depth（空间）**
   - 景深
   - 前、中、后景层次
   - 空间纵深
   - 空气透视
6. **Quality（画质）**
   - 曝光与动态范围
   - 噪声、清晰度、纹理
   - 压缩痕迹
   - 白平衡与色偏
7. **Composition（构图）**
   - 画幅与机位
   - 透视
   - 主体位置
   - 地平线
   - 建筑或地貌结构
8. **Narrative（叙事）**
   - 视觉叙事倾向：纪实、旅行、商业、电影感、安静、人文、力量感等
9. **Risk（保护风险）**
   - 列出后期中最容易被误改的区域，包括脸部、建筑、地貌、天空、反射、动物形态等
   - 每个区域都需写明具体风险，例如变形、失真、色彩偏移

## 4. 分析原则

1. **先事实，后审美**：先完成第 3 节全部事实维度的识别，再给出审美或叙事判断。
2. **画面观感不等于风格强度需求**：不得因为“当前照片不好看”就推断需要强风格。风格强度只能由总规则源中的评分与总分带决定。
3. **禁止反推**：不得根据风格名称倒推照片条件。分析阶段不参考任何候选风格。
4. **不确定即标注**：无法确认的内容标记为 `uncertainty`，并给出相应的低 confidence。不得用猜测值填充。
5. **光线方向优先**：原始主光方向属于高优先级事实。后续选用的任何技术都不得改变或违背该方向，例如不得在逆光照片上做出与主光源相矛盾的明暗塑形。

## 5. 输出要求

- 输出结构以 `schemas/photo-analysis.json` 为准，字段名与枚举值不得自行扩展。
- 所有关键判断都应附带 `confidence`，取值范围为 0–1。关键判断至少包括：主体类别、场景类别、主光方向、色温、叙事倾向和 Risk 区域。
- 标记为 `uncertainty` 的字段必须保留在输出中，不得省略。
